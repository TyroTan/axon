# Claude Code Harness — working artifacts

These are the real files from my daily AI-native development environment (a Go + TypeScript
multi-product monorepo), published as-is except for path genericizing and an excerpt cut of
the directive corpus. They are the "system, not the habit": the quality bar is encoded in
files the agent loads every session, not in habits a reviewer has to remember.

## Artifacts

- **[CLAUDE.md](CLAUDE.md)** — the lean project index. Deliberately small (~85 lines): it is a
  *pointer*, not the doctrine. It defines the unconditional trigger keywords (`distill`,
  `spiral`, …) that force a search-for-equivalents gate before any build, the blast-radius
  grep rule for domain constants, and where the real doctrine lives.

- **[directives_excerpt.md](directives_excerpt.md)** — 4 of the 17 curated directives that a
  SessionStart hook injects into every session (the full corpus lives in a versioned store and
  the cache is regenerated by a test). Included here: the durable work-queue state machine
  (CCQ), the Continuous Verification Probe lifecycle, the deterministic pre-commit gate, and
  the cheap-first verification ladder.

- **[hooks/clauding.sh](hooks/clauding.sh)** — the SessionStart hook wrapper. Builds the
  injector binary on first use, fail-silent by design so a hook failure can never block a
  session. This is the mechanism that makes the directives ambient instead of relying on the
  agent to go read them.

- **[mcp.json](mcp.json)** — the MCP wiring for the retrieval server the agent uses daily:
  document/doctrine query tools per subsystem, signal capture, and a multi-hop `deep_recall`
  tool (sparse ⊕ dense retrieval, judge-loop reformulation, and a preview mode that quotes the
  synthesis cost *before* spending it).
